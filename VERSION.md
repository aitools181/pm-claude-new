# Version history

Convention: **MAJOR.MINOR** — bump MAJOR for a big update (new capability area,
breaking change, major release), MINOR for a small change (fix, tweak, small addition).
The running version is shown only in the platform console (`/superadmin`), next to the title.

To change it, edit `packages/shared/src/version.ts` (`APP_VERSION`) and the root `package.json`.

| Version | Date | Summary |
|---------|------|---------|
| 6.2 | 2026-08-13 | The web container was proxying `/api` and `/socket.io` to itself. Next evaluates `rewrites()` during `next build` and bakes the destination into `routes-manifest.json`; `INTERNAL_API_URL` was set only on the running container, so the destination baked as `http://localhost:4000` and every API call came back as a plain-text 500 - the "Request failed" seen on login, and silently broken realtime. `INTERNAL_API_URL` is now a build arg, and the image build fails outright if the destination ever bakes to localhost again. |
| 6.1 | 2026-08-13 | Errors say what actually went wrong. `AppErrorFilter` was `@Catch(AppError)`, so any other exception fell through to Nest's default filter and returned `{statusCode, message}` - a shape the web client does not read, which is why a failed login showed only "Request failed". The filter now catches everything, keeps one response shape, logs the real stack server-side, and returns a short summary. The client also appends the HTTP status when no message is supplied. |
| 6.0 | 2026-08-13 | Sign in works again, and sign out is always reachable. Two independent defects blocked login: form buttons defaulted to `type="button"` so clicking never submitted, and the submit button was disabled whenever React state for email/password was empty - which browser autofill leaves empty, so pressing Enter did nothing either. Auth forms now read values from the form itself, validate on submit with a visible message, and only disable while a request is in flight. Adds a dedicated `/logout` route and a Log out entry on the product rail, alongside the account menu, sidebar footer and Settings -> Account. Also adds error boundaries (`app/error.tsx`, `app/(app)/error.tsx`, `app/global-error.tsx`, `app/not-found.tsx`) so a render failure shows a readable message with a retry instead of a blank white page, and a browser regression spec at `apps/web/e2e/auth-signin.spec.ts` covering all of the above against a stubbed API. |
| 5.9 | 2026-08-13 | Sign in (and every other form button) works again. `Button` defaults to `type="button"`, so the primary buttons inside `<form onSubmit=...>` never submitted — clicking "Sign in" did nothing at all, with no error, because the handler never ran. Only Enter in a field worked. Every in-form submit button now sets `type="submit"` explicitly: login, password recovery, password reset, invitation accept, project/board task create, add section, subtask and checklist add. |
| 5.8 | 2026-08-13 | API boot diagnostics. A failed database migration now prints the reason and a targeted hint instead of disappearing behind the orchestrator's generic "container is unhealthy". Documents the Postgres behaviour where `POSTGRES_PASSWORD` is applied only when the data volume is first created, which is what made the API exit ~5s after start. |
| 5.7 | 2026-08-13 | Production build fix and sign-out recovery. `/settings/account` now wraps `useSearchParams()` in a Suspense boundary and the whole authenticated `(app)` route group renders dynamically, so Next.js no longer fails prerendering one page at a time during the Coolify build. Log out is reachable from the account menu, the sidebar footer and Settings → Account, and all three share one helper that revokes the session, drops the socket and clears local cookies. |
| 5.2 | 2026-08-07 | Container health checks for api, web and worker, so the reverse proxy only routes traffic once a container is actually ready. Adds `/healthz` on web and a health listener on the worker. |
| 5.1 | 2026-08-07 | SMTP email delivery: instance mail settings in the platform console, password encrypted at rest, connection test with recorded result, and real delivery for invitations, password resets and verification (log adapter fallback). |
| 5.0 | 2026-08-07 | Platform console (instance admin, org suspension, module entitlements, platform flags, audit) and Plans & pricing (catalogue, editable prices, limits, plan-gated modules, public pricing page). Includes build fixes and core-flow repairs (default workspace on setup, workspace creation UI, multi-organization). |
